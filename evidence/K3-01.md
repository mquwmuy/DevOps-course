
# K3-01 — CI/CD и ветки

## CI/CD

CI (Continuous Integration) — автоматическая проверка кода
при каждом push или создании pull request.

Continuous Delivery — подготовка проверенного приложения
к выпуску. Решение о развёртывании принимает человек.

Continuous Deployment — автоматическое развёртывание
приложения после успешного прохождения всех проверок.

В моём проекте GitHub Actions запускается при push
или pull request. Сначала выполняются автоматические
тесты приложения, затем собирается Docker-образ.
Развёртывание приложения автоматически не выполняется.

## Схема работы с ветками

kt3 → Pull Request в main → CI → Проверка → Merge

1. Создаётся отдельная ветка kt3.
2. В неё вносятся изменения.
3. Создаётся Pull Request в main своей копии репозитория.
4. GitHub Actions запускает тесты и сборку.
5. После успешной проверки и приёмки работа сливается в main.

## Отличие от Git-flow

Git-flow использует дополнительные долгоживущие ветки:
develop, release и hotfix, а также feature-ветки.

Для небольшого учебного проекта достаточно короткой ветки
kt3 и основной ветки main. Это упрощает работу и проверку.

## Обратная связь

Если тест или сборка завершится с ошибкой, GitHub Actions
покажет неуспешный статус и сообщение об ошибке в логах.
Разработчик сможет исправить проблему до слияния веток.

## Вывод

Сборка Docker-образа не является автоматическим
deployment, поскольку образ только создаётся,
но не развёртывается на сервере.
