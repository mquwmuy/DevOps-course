\# КТ2-04. Локальный Registry



\## 1. Запуск Registry



Команда:



```powershell

docker compose --profile registry up -d registry

```



Результат: контейнер Registry успешно запущен.



\## 2. Отправка образа



Добавлен тег:



```powershell

docker tag devops-student:v1 localhost:5000/workshop:v1

```



Образ отправлен в Registry:



```powershell

docker push localhost:5000/workshop:v1

```



Результат: все слои успешно отправлены.



Digest:



```text

sha256:10071c7dafd56846f166cec59af4f825be78c6e55ef7ccbab2afe9e657913a68

```



\## 3. Скачивание и проверка



Команда:



```powershell

docker pull localhost:5000/workshop:v1

```



Результат: образ успешно скачан. Digest совпадает с полученным при отправке.



Проверка:



```powershell

docker image inspect localhost:5000/workshop:v1

```



В результате найдены теги `devops-student:v1` и `localhost:5000/workshop:v1`. В `RepoDigests` присутствует digest отправленного образа.



\## 4. Разница между тегом и digest



\- \*\*Тег\*\* (`workshop:v1`) - имя версии образа, которое можно изменить или переназначить.

\- \*\*Digest\*\* (`sha256:...`) - контрольный идентификатор содержимого образа, позволяющий точно определить версию.



\## 5. Ответ на вопрос для защиты



`docker push` не запускает приложение. Команда отправляет образ в Registry — хранилище образов. Чтобы запустить приложение, нужно создать контейнер, например с помощью `docker run`.
