
# K3-04 — Сборка после тестов

## Конфигурация

В Student CI добавлен отдельный job build.

Runner: ubuntu-latest
Зависимость: needs: test

Команда сборки:

docker build -f lab/Dockerfile -t devops-student:${{ github.sha }} lab

В job build используется checkout для получения
исходного кода репозитория.

Тег Docker-образа содержит SHA проверяемого коммита.

## Проверка зависимости

В тесте test_create_request ожидаемый статус
был временно изменён с 201 на 200.

Событие: push
SHA: 839c844cbedb2d6f0867511811809c618d3545f3

Ссылка на неуспешный запуск:
https://github.com/mquwmuy/DevOps-course/actions/runs/43492903915

Результат:

- test: failure
- build: skipped

Тест завершился ошибкой, поэтому зависимая задача
build не была запущена.

## Исправленный запуск

Ожидаемый HTTP-статус возвращён на 201.

Событие: push
SHA: 7ee928d333a481351d68736ca238c6765c3c1272

Ссылка на успешный запуск:
https://github.com/mquwmuy/DevOps-course/actions/runs/43493135704

Результат:

- test: success
- build: success

Все автоматические тесты успешно прошли,
после чего Docker-образ был собран.

## Объяснение

Конструкция needs: test создаёт зависимость между
задачами. Сборка выполняется только после успешного
завершения тестирования.

Это позволяет не тратить ресурсы на сборку
приложения, которое не прошло проверку.

## Вывод

Pipeline корректно выполняет тестирование и сборку
Docker-образа в нужной последовательности.

Образ остаётся на временном GitHub runner.
После удаления runner образ будет потерян,
если не отправить его в Docker Registry.
