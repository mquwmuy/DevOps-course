\# КТ2-05. Проверка ошибки подключения к API



\## 1. Изменение конфигурации



В `compose.student.yaml` временно изменён адрес API для сервиса `web`:



```yaml

API\_URL: http://api:9999

```



Применены изменения:



```powershell

docker compose -f compose.student.yaml up -d web

```



\## 2. Проверка ошибки



Просмотрены логи:



```powershell

docker compose -f compose.student.yaml logs --tail=50 web

```



В логах обнаружено:



\- `upstream\_unavailable`;

\- адрес `http://api:9999`;

\- ошибка `Connection refused`;

\- запросы к `/api/requests` возвращают `503`.



Вывод: веб-сервис работает, но не может подключиться к API, потому что указан неправильный порт.



\## 3. Восстановление работы



Адрес API исправлен:



```yaml

API\_URL: http://api:8000

```



Повторно применена конфигурация:



```powershell

docker compose -f compose.student.yaml up -d web

```



Результат: приложение снова работает, список заявок загружается.



\## 4. Вывод



Для связи сервисов внутри Docker Compose необходимо указывать правильное имя сервиса и внутренний порт. В данном случае правильный адрес — `http://api:8000`. Статус `healthy` у веб-контейнера сам по себе не гарантирует, что все запросы к API проходят успешно.
