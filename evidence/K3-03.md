
# K3-03 — Тестовый барьер

## Автоматические тесты

В Student CI добавлен шаг Run tests:

python -m unittest discover -s tests -p test_app.py -v

Тесты проверяют работу приложения, включая создание
заявки и получение правильного HTTP-статуса.

Первоначальный запуск завершился успешно:
https://github.com/mquwmuy/DevOps-course/actions/runs/43491639684

SHA: 2a83eaa766f5d959f9739a6e64a58e14ea1083f9

## Неуспешный запуск

В тесте test_create_request ожидаемый статус 201
был временно изменён на 200.

Статус: failure
Событие: push
SHA: ea4e65299fcb7b639dc183469345dfb36ff5f391

Ссылка:
https://github.com/mquwmuy/DevOps-course/actions/runs/43491951027

Строка из лога:

AssertionError: 201 != 200

Причина: приложение правильно возвращает HTTP 201
(Created), но тест ошибочно ожидает HTTP 200.

## Исправление

Ожидаемый статус возвращён на 201:

self.assertEqual(status, 201)

Статус: success
Событие: push
SHA: bc1ea6aeeab920f420d7aeee922d9998782ba6ed

Ссылка:
https://github.com/mquwmuy/DevOps-course/actions/runs/43492262841

Результат из лога:

Ran 7 tests in 1.712s
OK

## Вывод

Автоматические тесты работают как барьер качества.
Даже неверное ожидание в тесте приводит к ошибке CI,
поскольку фактический результат не соответствует
ожидаемому.

После исправления все 7 тестов успешно прошли.
