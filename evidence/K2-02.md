КТ2-02. Собственный Docker-образ



1\. Dockerfile



Создан файл `lab/Dockerfile` на основе `python:3.13-slim-bookworm`



2\. Сборка образа



Команда:



```powershell

docker build -f lab/Dockerfile -t devops-student:v1 lab

```



\*\*Результат:\*\* образ `devops-student:v1` успешно собран



Проверена метка `course.student` со значением `13052008`



3\. Запуск контейнера



Команда:



```powershell

docker run --rm -d --name student-web -p 127.0.0.1:8081:8000 -e ROLE=web devops-student:v1

```



\*\*Результат:\*\* контейнер `student-web` успешно запущен.



4\. Проверка приложения



Команда:



```powershell

curl.exe -i http://localhost:8081/health

```



Ответ сервера:



```json

{"process": "running", "role": "web"}

```



HTTP-статус: `200 OK`



5\. Логи и остановка



Команда просмотра логов:



```powershell

docker logs student-web

```



В логах зафиксирован запуск приложения и успешные запросы `GET /health` со статусом `200`



Остановка контейнера:



```powershell

docker stop student-web

```



\*\*Результат:\*\* контейнер остановлен.



6\. Объяснение Dockerfile



\- `FROM` -выбирает базовый образ Python

\- `WORKDIR`- задаёт рабочую папку `/app`

\- `ENV` - настраивает переменные окружения Python.

\- `COPY`- копирует `app.py` и `index.html` в образ.

\- `RUN`- создаёт `/data` и выдаёт пользователю с UID/GID `10001` права владельца этой папки

\- `USER` -запускает приложение от имени `10001:10001`, а не от root

\- `EXPOSE`- указывает, что приложение использует порт `8000` внутри контейнера

\- `LABEL` - добавляет метку с кодом студента.

\- `CMD` -задаёт команду запуска приложения.



7\. Ответ на контрольный вопрос



`EXPOSE 8000` сам по себе не открывает порт контейнера на компьютере. Параметр `-p 127.0.0.1:8081:8000` связывает порт `8081` компьютера с портом `8000` контейнера. Поэтому приложение доступно по адресу `http://localhost:8081/health`.
